# Benchmark: initial load and daily run at 1× and 10×

Generated by `scripts/benchmark.py` on 2026-11-16; arm64 macOS, PostgreSQL 16, DuckDB, everything on one laptop (Apple M2, 16 GB). Seconds are wall-clock per step from `etl.step_run`.

Method: **1×** simulates the whole history (1 Jul 2022 → 2026-10-31) and loads it with a full refresh; **10×** runs the simulator with `--scale 10` (ten times the couples, so about ten times the daily inquiries, messages and bookings) over a shorter window (1 Jul 2022 → 2023-03-31) to keep simulation time sane. Each case then simulates 3 more days and loads each with the normal incremental run. Silver is rebuilt from the whole Bronze history every run, so a daily run's cost grows with history (CRM sizes below) as well as with daily volume.
